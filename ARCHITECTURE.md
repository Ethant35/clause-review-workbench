# Architecture

Author: Ethan

Clause Review Workbench is a single-user, local contract review aid. It does not provide legal advice or replace attorney review. A React/TypeScript browser client talks to a FastAPI service on loopback. SQLite stores document metadata, extracted blocks, playbooks, immutable playbook snapshots, and reviews. Original bytes are stored separately under random UUID names, with a SHA-256 digest.

## Extraction and evidence

File signatures and content select DOCX, PDF, or UTF-8 text parsing. DOCX body paragraphs, including table cells, retain their order. PDF text blocks retain page numbers. Text anchors retain line numbers. The canonical extracted text joins blocks with two newlines. Anchors contain block ID, exact text, start/end Unicode code-point offsets, and source location. These offsets describe extracted text, not original ZIP/PDF bytes. Every issue quote is checked against a stored block and canonical text before persistence. Missing-provision findings have null quote and anchor, an explicit absence flag, and NEEDS_REVIEW confidence.

Binary extraction runs in a disposable subprocess with a 15-second wall limit, 10 CPU seconds, and a Linux address-space limit where available. Uploads, ZIP expansion, PDF pages, text size, and block counts are bounded. DOCX tracked changes, text boxes, notes, embedded imports, macros, content controls, fields/drawings, and hidden text are rejected. Hidden-style checks resolve inherited paragraph/run styles and default paragraph/run formatting. DOCX body paragraphs and nested table cells retain XML order; headers/footers and comments are excluded with visible warnings. PDFs with raster images or textless pages are rejected. PDF annotations/comments/form fields are not extracted and trigger a warning; side-by-side blocks or exhausted layout-pair checks also trigger warnings. The parser does not guarantee visual PDF reading order. Inspect originals.

## Analysis

Layer A uses the selected versioned YAML conditions. Presence patterns locate candidate blocks. Recognized negation, unresolved cross-references, open-ended qualifications, and mixed liability/indemnity scope first trigger conservative abstention. Remaining unacceptable matches produce objective pattern findings; every acceptable group must match a candidate block before COMPLIANT is returned. Other identified language becomes NEEDS_REVIEW. A second inconsistent clause prevents a clean result. Common number words and typography are normalized only for matching; quotations remain unchanged. Explicit liability-cap properties identify a fee basis and period separately from cap exceptions. These are narrow string-pattern facts, not conclusions about enforceability.

Layer B is isolated in `backend/workbench/ai.py`. It is called only through an explicit-consent endpoint. OpenRouter authentication and provider endpoint prices are checked before contract transmission. One configured model and explicitly selected provider are used, with fallback disabled. Input size, output tokens, estimated dollar cost, and provider maximum prices constrain each request. The attempt is durably recorded as `IN_PROGRESS` before transmission. If transmission may have started but the outcome is unknown, the state is `OUTCOME_UNKNOWN`; startup converts interrupted `IN_PROGRESS` attempts to that state. The app never retries automatically because a charge may have occurred. All AI findings remain `NEEDS_REVIEW` even when quotations match. Invalid quotes or rule IDs reject the entire response; the offline review and reviewer decisions remain available. This workflow is not qualified for legal accuracy.

## Persistence and deployment

Each SQLite write is transactional. Reviewer decisions use an immediate transaction to avoid lost writes. Review history retains the playbook snapshot used at analysis time. Changes to a playbook affect later reviews only. API/UI/export guidance is derived from that saved snapshot, including alternatives and optional fallback wording. Document and review APIs paginate at a maximum of 100 items per request; the history endpoint offers a summary projection that omits issues, checks, snapshot, and AI audit/error details. Extraction revision 4 and review revision 4 mark the checks used. Saved analysis, decisions and policy snapshots are preserved; startup only marks interrupted AI attempts as OUTCOME_UNKNOWN. Read/export views add a historical warning, and new analysis requires a fresh upload when extraction checks changed. Retention runs at startup and once per minute. Deleting a document cascades to all reviews and removes its original. Exports downloaded by a user are outside server retention.

The supported `scripts/start.sh` launcher uses a preinstalled `.venv`; it does not install packages. Set up a local environment with `uv sync --frozen --python 3.12 --no-dev`, then build the frontend before launching. Production serves the built frontend from the backend. Development uses Vite's same-origin `/api` proxy. The local boundary limits request sizes and concurrent work and writes bounded private diagnostics without source payloads. No remote scripts, fonts, analytics, or paid hosting are required. Current readiness evidence covers only a single-user local macOS setup; this is not a multi-user service and must not be exposed to a network without authentication, authorization, transport protection, and isolation.

## Cross-clause evidence (review revision 4)

`relations.py` runs after per-rule evaluation. It returns bounded relationships for active rule IDs. `engine.py` attaches them to findings, validates every related block against the stored extraction, preserves ISSUE outcomes, and marks otherwise qualifying checks NEEDS_REVIEW. It does not execute contract instructions or infer precedence. The `interactions` field is additive: kind, explanation, evidence array, and optional reference/status. Older reports without the field still export. The UI navigates by exact related block ID.

Supported recognition is deliberately narrow: explicit fee-based aggregate caps, named cap exceptions/indemnity uncapped wording, quoted or expressly stated Fees definitions, sentence-bound convenience termination costs, and qualified references to explicit Section/Clause labels. Separate caps are candidate matches by named category, not proof of identical party/claim scope. Consequential-damages exclusions do not automatically become monetary-cap exceptions. Reference traversal has six-level and 64-visit limits; evidence over 64 blocks or more than 100 interactions produces HTTP 422 with no stored review. All matching retains the existing time budget.

Review revision and extraction revision are distinct. Review revision 4 changes analysis; extraction revision 4 adds hidden-style/default-style checks. Existing extraction-revision-4 uploads can be rerun with current review logic; older extractions require re-upload. Old decisions and notes are preserved with a visible historical warning. The v1.2.0 evidence is specific to local test workflows and does not establish broad contract accuracy or qualify optional AI as legal analysis.
