# Contributing

Author: Ethan

Use Python 3.12+, Node 22+, uv, and the documented development commands. For development dependencies, run `uv sync --frozen --python 3.12`; for the local runtime only, run `uv sync --frozen --python 3.12 --no-dev`. `scripts/start.sh` expects the runtime environment to exist already and does not install it. Keep changes on a feature branch. Preserve MIT licensing and source evidence. Do not add analytics or network dependencies to offline review.

The suite includes focused Python tests, real HTTP/API workflows, browser checks, persistence, parsers, and exports. Use focused tests to reproduce a defect before changing the implementation, and preserve independent positive and negative controls. New legal screening behavior needs independently written synthetic fixtures and stable rule IDs before scoring application output. Do not weaken manifests to match observed results. Document ambiguity honestly. Property-based tests should assert bounded invariants over generated inputs; they do not establish legal accuracy or native parser-library coverage.

Run `uv sync --frozen --python 3.12`, `npm --prefix frontend ci`, `npm --prefix frontend run build`, focused pytest coverage, and the applicable `.venv/bin/python tests/e2e.py`, `.venv/bin/python tests/adversarial_e2e.py`, and `.venv/bin/python tests/upgrade_e2e.py` suites. The upgrade suite needs the actual v1.0.0 Git tag and uses the released server to create its initial database. Run `scripts/clean_acceptance.sh` before release. Inspect export rendering and browser screenshots. The v1.2.0 test inventory was reported as 84 pytest tests plus 2 subtests; that count does not qualify legal accuracy. See [analysis readiness](docs/readiness-analysis.md) and [local recovery](docs/recovery.md). Do not commit contracts, keys, local databases, downloaded reports, or logs. Use synthetic examples only. Personal author metadata on repository-generated documents is Ethan; factual application metadata remains truthful.

No GitHub Actions: do not create workflows or dispatch them. Check `gh api repos/Ethant35/clause-review-workbench/actions/permissions` before pushes/tags and ensure `enabled` is false. Submit a pull request with local checks, limitations, and any externally blocked provider validation.
